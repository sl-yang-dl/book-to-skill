# book-to-skill reader(元技能)

把一个「已转成 markdown 的书」变成一份**你读得懂、Pi 也能加载**的读书笔记 skill。

## 何时使用

- 用户给了一本书的 `.md` 全文路径,要求产出读书笔记。
- 想为个人知识库积累「书 → skill」格式笔记。
- 周期性复盘某本书的收获。

## 输入

- 一本书的 `.md` 全文路径(可能很大,需分块读取)。
- 书名 / 作者(从文件名或正文推断)。

## 步骤

1. **通读**:分块读完整本书,先抓目录与章节结构(留意 `##` 分段、序/跋/工具箱等标志性章节);**顺手抽取标题层级树**,用作「全书大纲 · 思维导图」(mermaid mindmap)。
2. **抽取七块骨架 + 5 个通用块**:把内容填进 `references/note-template.md` 的模板。
   - 块 1–4 为 **faithful 抽取**(忠于原书,不加个人发挥);**导览(全书脉络+书目)**、**全书大纲(思维导图)**、**金句摘录** 与 **本书提及书单(表格)** 同样为忠实抽取(大纲可由源 markdown 标题树自动生成;书单从正文/注释引用的《书名》抽取)。
   - 块 5–7 为 **综合块**,v1 先留**引导式空模板**(由读者本人填写);**评价与适合人群** 也为综合块,见决策 D6。
3. **产出笔记 skill**:
   - `SKILL.md`(薄):frontmatter 的 `description` **写满书主题与触发场景**,让 Pi 日后能自动路由加载;
     并补充 `tags: [主题词1, 主题词2]`(如 `[写作, 方法]`),用于在网站书架做标签筛选;
     正文只放一句话来源说明 + 指向 `references/note.md` 的指引。
   - `references/note.md`:七块骨架的完整抽取结果。
4. **命名**:笔记 skill 目录建议用 `samples/<书名>/`。
5. **发布(闭环)**:笔记产出后,调用 `publisher` 技能(`publisher/SKILL.md`)把站点同步并推送上线,
   实现"解析完一本书 → 网站自动更新"。本地可直接 `cd site && npm run publish`。

## 七块骨架(D5)

1. 核心论点 — 这本书到底在主张什么
2. 心智模型 — 可用以思考 / 行动的结构化框架
3. 论证证据 — 原书用来支撑的关键例子、引文、数据
4. 反例边界 — 何时不适用、作者自己承认的例外
5. 与我连接 — (读者填)它和我已有的 X 有什么关系
6. 可执行下一步 — (读者填)我能拿它做啥
7. 未解问题 — (读者填)我哪里不同意 / 还想追问

## 五个通用补充块(扩展)

- **导览 · 全书脉络与书目**(faithful):一句话总结 + 全书结构地图 + 书名/作者/版本/阅读情境。
- **全书大纲 · 思维导图**(faithful):mermaid `mindmap` 呈现章节层级树(可由源 markdown 标题自动抽取),便于鸟瞰与回查。
- **金句摘录**(faithful):写推文 / 笔记时最想直接抄的原句,附出处章节。
- **本书提及书单**(faithful):表格呈现本书正文/注释引用、提及的其他书目(书名/作者/简介),结构化内容可用 table。
- **评价与适合人群**(综合):总体评分、适合谁读、不适合谁 / 局限、延伸书单与已读对照。

> 七块是核心骨架(D5);五个通用块补足"鸟瞰 / 章节地图 / 可复用原句 / 提及书单 / 选书决策"五件一般读书笔记都该有的事。

## 与机器检索索引的区别(D7)

本笔记**不是** RAG 索引。它要求写「与我连接 / 可执行 / 未解问题」,产出的是
"你读过的证据 + 个人知识沉淀",而非"这本书讲了啥、问啥答啥"。人读友好优先。

## 全链路自动化

1. **reader**(本技能):书 → `samples/<书名>/` 笔记 skill(七块骨架)。
2. **publisher**(`publisher/SKILL.md`):笔记 → 同步进 VitePress 站点 → push → GitHub Pages 自动部署。
两步串起来即"喂一本书 → 产出笔记 → 网站更新"的闭环。

## 注意

- 只读抽取,不擅自改动原书 markdown。
- 大书分块读,避免截断;保留原书章节锚点(如 `## 工具箱`)以便回查。
